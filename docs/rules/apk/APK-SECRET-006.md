# APK-SECRET-006 — ключи провайдеров внутри APK

**Статус:** реализовано (`src/apk_audit/rules/secret.rs`, пул строк DEX — `src/apk_audit/dex.rs`).
**Категория:** `secret_exposure`. **CWE:** CWE-798 (Use of Hard-coded Credentials). **MASVS:** не сопоставлено.

## Что проверяется
Матчеры ядра (`secrets::rules::scan_line`, с префильтром) — без дублирования — по:
- текстовым записям (нет NUL в первых 8 КБ): `assets/**`, `*.json`, `*.properties`, … — построчно,
  с номером строки в записи;
- строковым значениям атрибутов во всех AXML-записях (`AndroidManifest.xml`, `res/**/*.xml`) —
  место указывается как путь элемента и атрибут (`resources/item@value`), без номера строки;
- **пулу строк `classes.dex`, `classes2.dex`, … в корне APK** (ADR-DEX, одобрен 2026-11-12): только
  строки, без байткода. Многострочная строка проверяется построчно.

| Ключ | Источник | Severity / Confidence |
|---|---|---|
| привилегированный формат (Stripe `sk_live_`, GitHub, OpenAI, приватный ключ, …) | текст, AXML | critical / potential |
| то же | DEX | **high / potential**, тег `source:dex` (строка может принадлежать встроенной библиотеке) |
| Google API key `AIza…` (обычно публичный ключ Firebase/Maps) | любой | info / needs_review — «проверьте ограничения ключа» |

APK может скачать кто угодно, поэтому любой привилегированный ключ в нём — у всех. Potential: формат
совпал, но действителен ли ключ — не проверяется (сети нет). Заглушки (`sk_live_xxxx…`) отсеивает ядро.
В отчёте только маска ядра и отпечаток (тот же, что у `jetscan secrets`). Не больше 200 срабатываний на
запись (и на DEX) — дальше `partial`.

**Приватный ключ PEM** — находка только если после заголовка `-----BEGIN … PRIVATE KEY-----` до
`-----END` есть тело base64 не короче 64 символов (самый короткий реальный ключ — Ed25519 PKCS#8 — 64).
Строка DEX, атрибут AXML и остаток текстового файла известны целиком, поэтому это проверяется; строка,
где есть только заголовок (утилиты разбора PEM), — не ключ (полевой тест 2026-11-12, FP-паттерн 11).

### Находки из DEX: что сообщаем как место
- `archive_entry` — DEX-файл (`classes2.dex`); `component` — `string_ids[N]` (индекс строки в его пуле);
- теги `byte_offset:<смещение string_data_item>`, `also_in:<другие DEX с тем же значением>`;
- `line` — **всегда пусто**. Класс и строку исходника не называем: байткод не разбирается.

Одно значение — одна находка на весь APK (дедуп по отпечатку), даже если оно в нескольких DEX (multidex).

### Пул строк DEX: защита от враждебного входа
Версии 035–039; 041 (контейнер) и обратный порядок байт → проверка `partial` с причиной. Лимиты: строк в
пуле ≤ 1 000 000 (проверяется до чтения), строка ≤ 1 МиБ, ≤ 200 `classesN.dex` на APK. Смещения строк
дедуплицируются, декодированных байт — не больше области данных DEX (миллион id на одну строку не
превращается в терабайт работы). Битый MUTF-8 → `U+FFFD`; несовпадение Adler-32, `map_list` или
`file_size` — строки в limitations; пропущенные строки → `partial`.

## Вне рамок (считаются и указываются в limitations)
Код DEX (байткод), DEX/JAR/ZIP/APK внутри APK вне корня (`assets/payload.dex` — упаковщики, динамическая
загрузка), `resources.arsc`, `lib/**` (нативный код), картинки и медиа, `META-INF/` (подписи).

## Фикстуры
Значения собираются в тесте в рантайме, в репозиторий ключеподобные строки не попадают. DEX собирается
тестовым сборщиком вручную (`src/apk_audit/dex/tests.rs`, вариант B ADR-DEX): независимого оракула
(`dexdump`/`d8`) пока нет — загрузка не одобрена; тест устроен так, что сверку с `dexdump` можно добавить
позже. Тесты: `secret_006_text_axml_and_out_of_scope_entries`, `secret_006_dex_string_pools`,
`secret_006_dex_hit_cap_is_partial`, модульные тесты `dex::tests` (MUTF-8 по байтам из спецификации,
версии, бомбы, алиасинг смещений, каждое усечение, 20 000 мутаций).

## Ограничения
Что строка принадлежит библиотеке, а не коду приложения, без байткода не определить — поэтому DEX-находки
`high`, а не `critical`. Неиспользуемые строки (если R8 их не вырезал) тоже будут найдены.
